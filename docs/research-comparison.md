# Choosing a learning technique for coding corrections

Reviewed 2026-10-18. This comparison concerns a **local, opt-in coding-correction tool**. Results from different papers use different tasks and are not comparable as a single leaderboard. None measures this project's real-world correction reduction.

| Technique | Reported benefit and mechanism | Fit here |
|---|---|---|
| [Reflexion](https://proceedings.neurips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html) | Verbal reflection on feedback improves later trials without changing model weights; includes coding experiments. | Useful idea for extracting a draft after a failure, but a self-written reflection is not developer authorization or verified evidence. Keep any draft review-gated. |
| [ExpeL](https://ojs.aaai.org/index.php/AAAI/article/view/29936) | Accumulates experiences and natural-language insights from training tasks, then retrieves them at inference. | Could transfer recurring patterns, but needs task trajectories that this privacy-minimal product does not collect. |
| [ACE](https://arxiv.org/abs/2510.04618) | Structured, incremental playbook updates avoid losing detail through repeated summary rewrites; reports gains on AppWorld and finance benchmarks. | Strong fit for immutable lesson revisions and small approved updates. Its published gains do not establish gains here. |
| [Mem0](https://arxiv.org/abs/2504.19413) and [A-MEM](https://proceedings.neurips.cc/paper_files/paper/2025/hash/19909c36f51abc4856b4560aff3d36d6-Abstract-Conference.html) | Scalable selective memory and adaptive links help long-term conversational recall. | More flexible for vague queries, but model-assisted ingestion and embedding/link maintenance add cost and private-data flow. Their conversation-memory results do not justify those costs for a small correction store. |
| [Structurally Aligned Subtask-Level Memory](https://proceedings.mlr.press/v306/shen26ad.html) | Aligns storage and retrieval with software-agent subtasks; reports mean +4.7 percentage points Pass@1 over a vanilla agent on SWE-bench Verified. | Most directly relevant domain evidence. A correction about a screen should require screen context, even when an API task shares its broad topic. |
| [Repository memory for code localization](https://www.microsoft.com/en-us/research/publication/improving-code-localization-with-repository-memory/) | Uses commits, linked issues and changing-module summaries to improve file localization. | Valuable for a separate localization feature, but it does not establish a developer preference and requires repository-history ingestion. |
| [LongMemEval-V2 AgentRunbook-C](https://arxiv.org/abs/2605.12493) | Coding-agent evidence gathering beat a RAG baseline on environment-memory questions; authors note high latency. | A later offline audit option if a large evidence corpus exists. Its web-environment benchmark is not this product's task, and prompt-time cost is too high for the local hook. |

## Choice

Use **ACE-style incremental, human-approved lesson revisions** with **subtask-level applicability** and deterministic scope, expiry, exception and conflict gates. Keep the existing SQLite FTS5 index for candidate retrieval. The new optional `--requires` terms must **all** appear in a task, while at least one `--when` term must appear. This supports a narrow lesson such as `--when auth --requires screen`, which is suppressed for “fix auth API”. More specific approved lessons shadow a general lesson with the same trigger and exception set when their required context matches. The setting is optional so older lessons retain their behavior and hashes.

The choice follows the closest software-engineering evidence while preserving local operation, manual approval, low-latency retrieval and the ability to explain abstention. [LongMemEval](https://arxiv.org/abs/2410.10813) highlights knowledge updating and abstention as memory abilities; this project already has revisions, expiry and conservative overlap handling. [OWASP's memory-poisoning analysis](https://genai.owasp.org/2026/05/13/memory-is-a-feature-it-is-also-an-attack-surface/) reinforces keeping retrieved lessons below user and host instructions.

## Local comparison and limits

`npm run eval:compare` runs five paired synthetic topics with screen tasks as positives and API tasks as hard negatives. Generic one-word triggers selected 5/5 positives and 5/5 negatives (precision 0.50). Required screen context selected 5/5 positives and 0/5 negatives (precision 1.00). This is an intentionally constructed retrieval test, not a model coding benchmark. It does not test synonyms, missing task details, natural developer corrections, or whether an agent follows a retrieved lesson. In ambiguous tasks, requiring explicit context favors fewer false suggestions and may miss useful lessons. Real A/B coding evidence would be needed before claiming improvement in developer outcomes.
