# Privacy

Agent Lesson Lab is local by default. The CLI has no telemetry, sync, remote model call, or always-on process. The optional Claude Code hook reads a submitted prompt in memory to select approved lessons; it does not persist the prompt. The portable skill operates only when an agent invokes it.

A `capture` command saves the short title, lesson, applicability terms, verification instruction, repository identity, and revision/audit metadata supplied by the developer. It does not save the original chat, source files, or a test transcript. Approval is labeled human review. The database is not encrypted, so anyone with access to your account or an unencrypted backup may read it. OS permissions restrict the data directory and files where supported; Windows relies on the account ACL. An input filter rejects common credentials and email addresses, but it cannot guarantee removal of all private information. Enter only generalized, non-sensitive summaries.

`attest` stores a short developer-reported outcome, distinctly labeled from an observed check. `run-check` stores the chosen command and arguments, result, runtime/platform, timestamp, and output byte count. It does not store stdout or stderr, because arbitrary test output cannot be reliably scrubbed of secrets. Command arguments are stored and filtered for common private patterns; avoid passing secrets as arguments. The explicitly chosen check runs in the project root and can have normal command side effects.

The store is under the OS user data directory: `~/Library/Application Support/agent-lesson-lab` on macOS, `%APPDATA%/agent-lesson-lab` on Windows, and `${XDG_DATA_HOME:-~/.local/share}/agent-lesson-lab` on Linux. Set `LESSONLAB_HOME` for an isolated store. `lessonlab backup` creates a copy under `backups/`. `lessonlab export --output PATH` writes a project-scoped JSON file outside the store and never overwrites an existing path. Exports and operating-system backups must be deleted separately by their owner.

`lessonlab delete ID --yes` removes one lesson's local revisions and audit, and **every local backup of the store**, including backups containing other projects. Backups contain the full database, so retaining one could restore the deleted lesson. `lessonlab delete --all --yes` removes all local lesson records and local backups. SQLite free pages are vacuumed; physical media, snapshots, system backups and prior exports are outside the CLI's control. `lessonlab disable` stops retrieval without deleting data. `lessonlab uninstall claude --yes` removes the owned hook, not the data. No retention timer is applied to lesson records; an optional expiry date stops retrieval but does not delete history.
